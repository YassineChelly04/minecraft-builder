🔧 Detailed Pipeline: Files, Models & Upgrade Paths

2️⃣ CLARIFY AGENT (Optional Brainstorm)
LLM Agent
📄 File
clarify_agent.py — Brainstorm + ask 2-4 clarifying questions
🧠 Model & Knowledge
Model: LLM_MODEL_CLARIFY or DEFAULT_MODEL
Default: llama-3.1-8b-instant (small, fast)
Temperature: 0.6 (creative brainstorm)
System Prompt:
"You are the lead architect's intake assistant.
Brainstorm the build (mood, style, pro touches).
Ask 2-4 clarifying questions about: scale, style, setting, rooms, features.
Output JSON with: brainstorm, assumptions, questions."
📤 Output
{
  "brainstorm": "2-4 sentences of design direction",
  "assumptions": ["defaults if user doesn't answer"],
  "questions": [
    {"id": "...", "question": "...", "options": [...]}   ]
}
🔧 How to Upgrade
• Change system prompt to ask different questions
• Override model: LLM_MODEL_CLARIFY=claude-3-sonnet
• Raise temperature for more creative brainstorm
↓
3️⃣ ORCHESTRATOR (Extract Intent)
LLM Agent
📄 File
orchestrator.py::get_intent() — Parse prompt + answers → structured intent
🧠 Model & Knowledge
Model: LLM_MODEL_INTENT or DEFAULT_MODEL
Default: llama-3.1-8b-instant
Temperature: 0.3 (deterministic JSON extraction)
System Prompt:
"Extract structured intent as JSON with schema:
{structure_type, size{x,y,z}, style, materials{walls,floor,roof,accent},
features[], notes}
Rules: valid Minecraft blocks, max 50 blocks/dim, minecraft: prefix"
📤 Output
{
  "structure_type": "house|warehouse|tower|...",
  "size": {"x": 10, "y": 6, "z": 10},
  "style": "modern|medieval|industrial|fantasy|...",
  "materials": {
    "walls": "minecraft:stone_bricks",
    "floor": "minecraft:oak_planks",
    "roof": "minecraft:dark_oak_planks"
  },
  "features": ["special elements"],
  "notes": "design direction for build agents"
}
↓
4️⃣ DETERMINISTIC SHELL (Envelope)
Python Logic
📄 Files
shell.py::build_shell() — Generate floor + 4 walls + roof + door + windows
blocks.py::VALID_BLOCKS — Curated set of valid Minecraft blocks (1.21.x)
🔍 Core Logic
1. Extract origin (x,y,z) and size (sx,sy,sz) from intent 2. Generate floor at y 3. Generate 4 walls from y+1 to y+sy-1 (using intent["materials"]["walls"]) 4. Generate roof at y+sy (flat or pitched based on style) 5. Cut door opening (1×2) in north wall 6. Cut window openings (1×1) in each wall 7. Fill interior air (y+1 to y+sy-1) 8. Return commands as list[str]
✅ Guarantees
✓ Always generates a complete, watertight envelope
✓ All blocks valid (checked against VALID_BLOCKS)
✓ Always has floor, roof, door, windows
✓ Respects user's material choices (with fallbacks)
✓ Never hallucinates block names
↓
5️⃣ PARALLEL BUILD AGENTS (Decorate + Furnish)
LLM Agents (Parallel)
⚙️ Execution
ThreadPoolExecutor(max_workers=2) runs:
  Agent 1: Exterior (facade detail)
  Agent 2: Interior (furniture)
Both complete before merge step.
EXTERIOR AGENT
exterior_agent.py::get_exterior_commands()
Role: DECORATE facade only (not structural)
Model: LLM_MODEL_EXTERIOR
Default: llama-3.3-70b-versatile (strong spatial)
Temp: 0.2 (low, deterministic)
"Add decorative facade details: decorative blocks, patterns, trim. NO structural changes. NO air blocks. Output minecraft commands."
• Style guide in system prompt
• Can request vines, signs, carpets, etc
INTERIOR AGENT
interior_agent.py::get_interior_commands()
Role: FURNISH interior only (furniture, decorations)
Model: LLM_MODEL_INTERIOR
Default: llama-3.3-70b-versatile (strong spatial)
Temp: 0.3 (slightly creative)
"Add interior furniture & decorations: beds, tables, chests, etc. Respect shell boundaries. NO air blocks. Output minecraft commands."
• Can request skill modules
• Use anchors (pre-computed safe coords)
• Reference furniture in skills/
🛡️ Safety: Air Block Stripping
_strip_air(commands) filters out any minecraft:air blocks from LLM output. This guarantees LLMs cannot punch holes in the watertight shell, even if they try.
↓
6️⃣ NORMALIZE → REPAIR (Deterministic Cleaning)
Python Logic
📄 Files
normalizer.py::normalize_commands() — Fix block names, strip invalid states
normalizer.py::merge_fills() — Combine adjacent /fill commands
repair.py::repair_commands() — Split oversized /fill, sanitize syntax
⚙️ Pipeline
1. normalize_commands(commands) - Fuzzy-match block names (e.g. "oak_plank" → "minecraft:oak_planks") - Strip invalid block states (e.g. "oak_planks[something=bad]" → "oak_planks") 2. merge_fills(commands) - Combine adjacent /fill commands into larger fills (performance) 3. repair_commands(commands) - Split /fill commands > MAX_FILL_VOLUME (32768) - Validate coordinate ranges (WORLD_MIN_Y=-64, MAX_Y=319) - Drop unfixable commands
✅ Guarantees
✓ Every returned command is syntactically valid
✓ No coordinates outside world bounds
✓ No /fill exceeds volume limits
✓ Block names fuzzy-matched to valid ones
✓ Invalid block states stripped
↓
7️⃣ OPTIONAL CRITIC (Review & Suggestions)
LLM Agent
📄 File
critic_agent.py::review_build() — Review interior furnishing, suggest additions
🧠 Model & Knowledge
Model: LLM_MODEL_CRITIC or DEFAULT_MODEL
Default: llama-3.1-8b-instant
Temperature: 0.1 (very precise)
"Review the interior furnishing. Is it complete? Suggest 1-3 additional furniture/decor that would improve the build. Output JSON with: {review, score, additions[]}"
📊 Input (Pre-computed Safe Anchors)
Critic receives anchors to avoid math:
• interior_center_floor
• interior_corner_floor
• front_door_floor
• ceiling_center
• wall_sconce
🔧 How to Upgrade
• Disable in UI if hitting rate limits
• Tune review criteria in system prompt
• Use stronger model for better suggestions
↓
8️⃣ FINAL VALIDATION
Verification
📄 File
validator.py::validate_commands() — Syntax & semantic check
✅ Checks
✓ All commands start with / (setblock, fill, etc)
✓ Coordinates are integers, within bounds
✓ Block names exist in VALID_BLOCKS
✓ No duplicate commands

🚀 UPGRADE STRATEGY (Easy → Hard)

Easy: Change model via env var
LLM_MODEL_BUILD=claude-3-sonnet python app.py

Medium: Modify system prompts
Edit orchestrator.py, clarify_agent.py, exterior_agent.py, interior_agent.py
Then restart app. Repair layer guarantees valid output.

Hard: Extend shell logic
Edit shell.py to add new architectural features (basement, balcony, etc)
Test with test_shell.py before production.

Expert: Refine repair heuristics
Edit repair.py for better block-name fuzzing or command merging
This affects all builds; test thoroughly.

⚠️ Never upgrade: blocks.py valid block set — must match Minecraft 1.21.x exactly
